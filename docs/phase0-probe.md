# 第 0 階段：可行性探勘清單

> 目的：在寫任何正式程式之前，先確認遊戲讓我們對貓做哪些事，再決定走方案 A、B 或 C（見 `pet-mod-plan.md` 第 3 節）。
>
> 預估時間：2–4 小時。
>
> 2026-10-20：PO 決定改走官方 ModKit（ADR 0005），本清單就是現行的第 0 階段。官方文件讀到的事實
> （MCP 位址、Lua API 是模擬層的覆寫模式、可能相關的型別、CLI 目錄沒有動物類別）整理在 `docs/modkit-route.md`。

## 準備

1. 啟動 inZOI，載入一個存檔。**準備一個測試用的 Zoi，把共存值調到 60 以上**，可以用作弊指令，或多做園藝、到公園走走。
2. 打開 ModKit 編輯器（測試 Lua 和 UI 時需要）。
3. 在 repo 資料夾開 PowerShell，執行 `claude`，確認 `/mcp` 裡的 `inzoi-game` 和 `inzoi-modkit` 都是 connected。
4. 下面每一題都可以**直接把「給 Claude Code 的指令」複製貼上**，本機的 Claude Code 會透過 MCP 自己去查遊戲。

## 探勘題目

### P1. 有哪些工具和指令可以用？
> 給 Claude Code 的指令：
> 「列出 inzoi-game 和 inzoi-modkit 兩個 MCP 伺服器提供的所有工具，每個附上一行說明。接著在 CLI 指令目錄裡搜尋含有 pet、animal、cat、coexistence、spawn、teleport、move、follow、relationship、need、buff、mood、notification、save、timer、event 的指令，**只列 Public 的**，整理成表格：指令 ID、參數、說明。把結果存成 docs/probe/commands.md。」

### P2. 能不能找到流浪貓？
走到附近有流浪貓的地方（街道、公園）。
> 「列出目前場景裡所有動物或貓的實體，給我它們的 ID、位置、類型，以及所有讀得到的屬性（例如和目前 Zoi 的關係值）。」

✅ 拿得到穩定的貓 ID → 方案 A 有機會

### P3. 能不能移動貓，或讓貓跟著 Zoi？
> 「把 P2 找到的其中一隻貓移動到目前 Zoi 的旁邊。如果沒有移動指令，看看有沒有讓牠跟隨 Zoi 的方法。」

接著讓 Zoi 回家（換地塊）：
> 「那隻貓現在還在嗎？在哪裡？」

✅ 跨地塊還能找到同一隻貓 → 方案 A

### P4. 能不能在家裡生成一隻貓？
回到家裡。
> 「在目前地塊、Zoi 旁邊生成一隻貓。有沒有可以設定外觀或品種的參數？」

✅ 可以生成 → 方案 B 可行

### P5. 存檔讀檔後還在嗎？
存檔、退回主選單、重新讀檔。
> 「P3 或 P4 的那隻貓還在嗎？ID 有沒有變？」

### P6. 能不能叫貓或 Zoi 做互動？
> 「讓目前的 Zoi 對旁邊的貓執行『餵零食』或任何貓互動。也試試看能不能讓貓單獨播放動作，例如睡覺、玩耍、坐下。」

✅ 可以觸發 → 照顧動作能有真的動畫

### P7. Lua 能不能定時執行？能不能存資料？
> 「用 inzoi-modkit 建一個測試 Lua 腳本模組：(1) 每個遊戲內小時在日誌記一行；(2) 把一個值（例如 pet_name = "咪咪"）存起來，存檔讀檔後再讀出來。告訴我 Lua API 有哪些事件、計時器、儲存相關的函式。把 Lua API 的重點整理成 docs/probe/lua-api.md。」

✅ 有計時器 → 需求可以隨時間下降；✅ 能存資料 → 寵物資料能跨存檔保留（不行的話，看 UI 端有沒有 localStorage 可以用）

### P8. UI 能不能做按鈕並呼叫指令？
> 「用 inzoi-modkit 建一個最小的 Overlay UI 模組：畫面右下角有一個『🐱』按鈕，按下去用 window.inzoi.cli.execute 呼叫一個 Public 指令（例如顯示通知），並顯示回傳結果。」

### P9. 能不能在原版的貓互動選單加一個「領養」選項？
> 「查 ModKit 的 Data 模組和 Script Condition / Script Execution 文件：能不能在流浪貓的互動選單新增一個自訂互動，並在點擊時執行我們的 Lua？」

✅ 可以 → 領養入口很自然；❌ 不行 → 改用 UI 按鈕

### P10. 狗和其他動物能做到什麼程度？（之後版本的參考）
> 「對城市裡的狗做 P2、P3、P6 的測試，牠有沒有任何互動或動作可以呼叫？」
