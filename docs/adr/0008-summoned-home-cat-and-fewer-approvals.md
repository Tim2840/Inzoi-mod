# 0008 家裡用召喚的貓呈現寵物；PO 只做大方向決定

- 日期：2026-10-21　狀態：**採用**　決定者：**PO（使用者）**　修訂：ADR 0007（方案）、ADR 0006（開發規則中的「每次都問」）
- **背景**：第 0 階段追加實測（`docs/phase0-results.md` P4）：資料腳本 `SpawnGameObjectToFront S1=DEV_Void_Cat` 能在 Zoi 面前召喚一隻
  **看得見**、可互動（原版「玩」「餵零食」）的貓，存檔後讀回仍在（同一實體 ID 與座標），但**花色每次載入重新隨機**，而且只會原地待機。
  這是 Age of Magic／Witchcraft 系列模組使用的手法。另外 PO 表示希望減少逐項徵求同意，只做大方向指示。

## 決定

### 產品（修訂 ADR 0007）
1. **家裡的寵物用召喚的貓呈現**：領養後在家裡召喚一隻 `DEV_Void_Cat`，記下牠的實體 ID，當作這隻寵物在世界上的身體。
2. **資料與規則仍在 Lua 引擎**（B2）：需求、個性、成長、親密度、疏於照顧流程不變；Zoi 對這隻貓的原版互動經 `interaction.*` 事件計入引擎。
3. **UI 面板保留**：顯示名字、需求、心情、親密度、照顧按鈕與通知；存檔資料走 `wf.state`。
4. **花色**：目前無法固定，UI 與說明文字不得宣稱固定花色；找到固定方法前，花色只是外觀、不是寵物資料。
5. **城市認養**照 ADR 0007 保留。
6. `caps.spawn` 在「召喚」與「移除」都實測過之後才設為 true（CLAUDE.md 規則 5）。

### 工作方式（修訂 ADR 0006 的「每次都問 PO」）
7. **PO 只做大方向指示**（方案、優先順序、規格取捨）。下列事項 Dev 自行決定並在段落結束時一次回報：
   - 實作細節、探勘與測試的設計、分支與提交；
   - **合併進預設分支**：測試全綠＋CI 綠＋對照完成標準自我審查後即可 squash 合併並推送（不必逐次問「可以合併」）；
   - **遊戲操作**：啟動遊戲、載入存檔、在測試中操作遊戲；寫入存檔前先備份兩個存檔資料夾並核對，能不存檔就不存檔。
8. **仍然一定先問 PO**：下載或安裝任何東西、發佈到外部平台（CurseForge 等）、改寫 git 歷史、刪分支、改預設分支、
   修改使用者的全域設定、覆寫或刪除 PO 的存檔（備份可還原的測試寫入除外）、PO 正在玩遊戲時操作遊戲。
9. 開始操作遊戲前先確認遊戲狀態；若不是 Dev 上次留下的狀態（例如 PO 正在玩），先停下來問。

## 後果
- `CLAUDE.md` 的開發規則改依本 ADR；`docs/engineering-workflow.md` 以本 ADR 為準。
- 2026-10-21 已實測移除：資料腳本 `DespawnGameObject BaseObject=Target` 可移除召喚的貓（被動保員帶走、被他人領養時用）。
  召喚與移除都已實測，`caps.spawn` 可在 adapter 實作完成並遊戲內驗證後設為 true。
- 下一步：依 ADR 0007＋0008 實作 `adapters/inzoi.lua` 與 UI bridge。
