# 0005 改走官方 ModKit 路線，UE4SS 路線暫停

- 日期：2026-10-20　狀態：**採用**　決定者：**PO（使用者）**　取代：ADR 0004
- **背景**：
  - ADR 0004 決定「先走 UE4SS，ModKit 當備案」。UE4SS 路線在 inZOI v0.11.0 上確實能注入、讀寫檔、掃描與傾印物件，也找到了城市裡的貓（紀錄在 `feat/observe-existing-cat`、`docs/t2-m1-3a-results` 兩個分支，未合併）。
  - 但同一天的實測發現：**裝著 UE4SS 時，「存檔後選單 → 遊戲結束」4 次全部崩潰**，崩潰點都在 `inZOI-Win64-Shipping.exe +0x22F5EC0`（存取違規），而且在**我們的 mod 全部停用**時照樣發生；**拿掉 UE4SS 後同一流程 1 次沒有崩潰**。UE4SS 上游的 PR #1415（2026-09-29 合併）修正了「離開遊戲時背景工作造成存取違規」，我們用的 UE4SS（`8f7b2ca3`，2026-09-24）不含這個修正。更新後的版本（`83330635`）是否解決，**未測**。
  - 讀官方文件（2026-10-20）：Lua 模組跑在遊戲的模擬層（B2），提供規則覆寫鉤子，並有生成、實體、時間、家戶、互動等系統型別（詳見 `docs/modkit-route.md`）。官方路線可以走 CurseForge 發佈、遊戲內模組管理器，不需要注入 DLL。
- **決定**：
  1. 主力改走**官方 ModKit**：Lua 腳本模組（模擬層）＋ Overlay UI 模組（`mod/ui/`），連接層是 `adapters/inzoi.lua`。
  2. 引擎（`pets/`、`data/`、`localization/`、`mod/ui/`）照 ADR 0001 維持共用 core，**不重寫**。
  3. UE4SS 路線**暫停**：`adapters/ue4ss.lua` 與相關工具留在預設分支，不刪除；兩個未合併的 UE4SS 分支保留當參考，不再開發。
  4. 第 0 階段照 `docs/phase0-probe.md`（P1–P10，透過 MCP）做，結果決定方案 A／B／C；**虛擬寵物（方案 C）是一定做得到的底線**。
- **後果**：
  - 官方文件**沒有任何動物、寵物、貓的型別或 CLI 類別**；能不能生成或控制貓、讓牠自己走動，要靠第 0 階段實測。「會自己走動的寵物」維持為**未證實的目標**。
  - 需要安裝 ModKit（Epic Games Store，免費；文件沒寫大小與系統需求），由 PO 登入 Epic 帳號。
  - 遊戲資料夾裡的 UE4SS 何時停用或移除，由 PO 決定（裝著它，離開遊戲時可能會出現上述崩潰）。
- **未決**：每戶隻數、是否老死、需求 3 或 4 個、合併後放哪個 repo；`docs/engineering-workflow.md` 與 `CLAUDE.md` 中「雲端 session 審查、四眼原則、通知雲端」的規則（雲端 session 已於 2026-10-20 退出）要怎麼改。
- **觸發重審**：第 0 階段證實官方 Lua 完全碰不到動物或生成，且 PO 仍想要會走動的寵物；或 UE4SS 更新後證實不再崩潰、PO 想恢復雙路線。
